## 1. Ledger Rules

- Each ID represents one root cause. Repeated function-level or cross-phase findings map to the same ID.
- Default owner is `Cockpit engineering`.
- Default implementation status is `planned`.
- `confirmed_fix` means the audit evidence is sufficient to implement the bounded correction.
- `verification_required` means the existing objective or live posture must be confirmed before implementation.
- `documentation_only` means runtime behavior is not to change.
- `retirement_required` means the safe correction is quarantine/decommission, not repair or reactivation.
- No item may expand or contract the affected function's original role.
- `DB/config impact` describes possible implementation impact; it is not authorization to apply a migration or deploy.
