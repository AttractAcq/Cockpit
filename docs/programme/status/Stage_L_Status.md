# Programme Stage L — Ad Studio and Paid Distribution

**Status: backbone implemented and deployed, live-verified against real database constraints with disposable fixtures. The real Meta Marketing API was deliberately never invoked live in this session — a safety decision, not just an untested code path. See "Deferred" below.**

## What this stage builds on

The context scan found `ads_master`/`ad_creative` (Stage B-era content-planning rows, read/written by `MastersPanel`/`Phase3CalendarPanel`/Reel Studio's source-row picker) and confirmed they are planning metadata, not campaign-execution objects — this migration adds a separate, canonical paid-content spine alongside them and does not touch either table. The scan also found a dead `meta-ad-ops` edge function that targets a `campaigns`/`entities` schema which does not exist in this database (the retired 7-workspace architecture `CLAUDE.md` documents as superseded). It is left in place, unextended, and superseded by this stage's real functions rather than deleted, consistent with this session's convention of not deleting code outside the current stage's declared scope.

Nothing else paid-related existed to preserve: no Ad Opportunity/Brief/Campaign tables, no Meta Marketing API adapter, no safety-policy gate. The entire "Ad Opportunity → Ad Brief → Creative Matrix → Campaign → Ad Set → Ad" spine the build plan describes is net-new this stage.

## Scope actually implemented (the "backbone")

### Schema — migration `20260809120000_stage_l_ad_studio_paid_distribution.sql` (applied live)
8 new tables, all RLS-enabled (`client_id = any(auth_client_ids())` select-only for `authenticated`, full access for `service_role`, matching every other stage's convention):
- `ad_opportunities` — the 8 origins the build plan names (`manual_idea`/`proof`/`research`/`campaign_requirement`/`organic_winner`/`performance_insight`/`offer_launch`/`seasonal_trigger`), with a CHECK enforcing `organic_winner` opportunities carry a real `promoted_from_content_opportunity_id` FK into `content_opportunities` — "Organic winners can be promoted without recreating the source manually" is a real foreign key, not a copied title.
- `ad_briefs` — the same 4-state lifecycle as `content_briefs` (Stage H precedent: `draft`/`in_review`/`approved`/`superseded`), structured `body` jsonb, `(ad_opportunity_id, brief_version)` uniqueness, an approval CHECK that ties `status = 'approved'` to both `approved_by` and `approved_at` being set together.
- `ad_creative_variants` — one row per Hooks×Visuals×Copy×CTA×Format combination, `source_provenance` jsonb recording the exact brief field indices it was generated from ("Creative variants retain source provenance"), a `(ad_brief_id, hook_index, visual_index, copy_index, cta_index, format)` uniqueness constraint that makes regeneration idempotent.
- `ad_budget_policies` — one row per client (`client_id` unique), every field the build plan's "Safety and approval" section names: `ad_account_owner_verified`, `payment_method_verified`, `spend_limit_daily`/`spend_limit_total`, `requires_client_approval`, `allowed_geographies`, `restricted_audience_flags`, `regulated_categories`.
- `ad_campaigns` — the Campaign state machine (`draft → pending_approval → approved → launching → active/failed → paused → completed → archived`), `(client_id, idempotency_key)` uniqueness ("Duplicate campaign creation is blocked"), `external_campaign_id` only ever set after a real Meta success, `client_approved_by`/`client_approved_at` recorded together (CHECK), `spend_to_date`/`impressions`/`clicks`/`conversions` for delivery metrics.
- `ad_sets`, `ads` — `ads` carries a `(ad_set_id, ad_creative_variant_id)` uniqueness so the same variant can never attach to the same Ad Set twice.
- `ad_launch_attempts` — an audit trail of every campaign-affecting action (`create_campaign`/`launch`/`pause`/`resume`/`update_budget`/`reconcile`), mirroring `client_publish_attempts`' role for organic distribution.

### Shared logic
- `_shared/ad-studio.ts` — `validateAdBriefBody` (strict structural validation mirroring `content-brief.ts`'s `validateStructuredBrief`), `renderAdBriefMarkdown`, `checkAdClaimGate` ("Unsupported claims fail" — a Brief self-flagged `proof_required` cannot approve without a linked verified Proof, same convention as Stage H's organic claim gate), `generateCreativeMatrix` — the full Hooks×Visuals×Copy×CTA×Format cartesian product, hard-capped at `MAX_VARIANTS_PER_BRIEF = 24` and failing closed (not silently truncating) when the product would exceed it.
- `_shared/ad-safety-policy.ts` — seven independent, pure gate functions (`checkAccountOwnershipPolicy`, `checkPaymentMethodPolicy`, `checkSpendLimitPolicy`, `checkGeographyPolicy`, `checkAudienceRestrictionPolicy`, `checkClientApprovalPolicy`, `checkRegulatedCategoryPolicy`) plus `checkLaunchPolicy`, which runs all seven in a fixed order and returns the first failure. `NO_POLICY` is the fail-closed default for any client with no policy row — every check fails against it, so a client that has never configured ad safety cannot accidentally launch anything.
- `_shared/meta-ads.ts` — a dependency-injected Meta Marketing API adapter, architecturally identical to `_shared/instagram-reels-publish.ts`'s proven Reels state machine: `createCampaignStep`/`createAdSetStep`/`createAdStep`/`activateCampaignStep`/`pauseCampaignStep`/`updateBudgetStep`/`fetchInsightsStep` are pure orchestration functions over an injected `MetaAdsDeps`, each returning a structured `{ok, value}`/`{ok, error}` result — never a fabricated success. `liveMetaAdsDeps()` is real, documented `fetch`-based Graph API integration code (verified against Meta's published Marketing API contract: campaigns always created `status=PAUSED` then explicitly activated, so a crash between creation and activation can never leave a campaign spending unattended) — see "Deferred" for why it is never called live this session.

### Edge functions (8, all deployed)
- `create-ad-opportunity` — validates origin against the 8-value enum, enforces the `organic_winner` → real source-row cross-client check.
- `manage-ad-brief` — `create`/`submit_for_review`/`approve`/`request_changes`. Approval re-validates the stored body, checks for a linked `verified` Proof item when `proof_required` is set, and on approval flips the parent Opportunity `shortlisted → selected`.
- `generate-ad-creative-variants` — idempotent (only inserts combinations not already present for the Brief), rejects with `MATRIX_TOO_LARGE` rather than truncating.
- `set-ad-budget-policy` — upsert on `client_id`, strict array/number validation before touching the database.
- `create-ad-campaign` — creates Campaign + one Ad Set + one Ad per selected creative variant, entirely in Cockpit's own database; **never calls Meta**; idempotent replay on `(client_id, idempotency_key)`; rolls back the Campaign row (cascading Ad Set/Ads) if any insert in the chain fails.
- `launch-ad-campaign` — the one function that can spend real money, and the most heavily gated: `checkLaunchPolicy`'s full seven-check gate runs and is logged to `ad_launch_attempts` **before any Meta credential is even read**. Credentials are read via the existing per-client `vault_read_credential` convention (`META_ADS` / `ACCESS_TOKEN`); with none configured anywhere in this project, every real launch attempt today fails closed at `MISSING_CONFIG` with an honest, non-fabricated error. Scope note left in the code: this creates the Meta Campaign and one Ad Set, then activates the Campaign — it does not yet create individual Meta Ad objects per creative variant (deferred below).
- `update-ad-campaign-status` — `pause`/`resume`/`complete`/`archive`/`reconcile`, each with its own `ALLOWED_FROM` state whitelist. `reconcile` mirrors the organic `reconcile_distribution_record` pattern exactly: the operator verifies real state on Meta themselves and tells Cockpit which outcome is true, never a blind automated guess ("Pause and resume reconcile").
- `update-ad-campaign-budget` — re-runs `checkSpendLimitPolicy` against the *new* requested budget before accepting it, so a budget increase can never bypass the same limit a launch would have been gated by ("Budget cannot exceed configured limit"); pushes the change to Meta too when the campaign is already live, same fail-closed missing-config pattern as launch.

All 8 functions share the existing `_shared/aa.ts` (service client, CORS, `json`, `audit`) and `_shared/ideation/auth.ts`/`access-policy.ts` (admin/account-manager-only access, matching every other Ideation-surface function this session).

## Deferred, with precise reasons

- **The real Meta Marketing API was never invoked live in this session — a deliberate safety decision, not an environment limitation.** `liveMetaAdsDeps()` is real, documented, fully-implemented `fetch`-based integration code, matching the exact contract Meta publishes for the Marketing API. But unlike every other external system this programme has live-tested with disposable fixtures (Higgsfield generations, Instagram Graph publishes), a real Meta ad launch spends real client money and cannot be "disposed of" the way a database row or a generated video file can. This project also has no Meta ad-account credentials configured, so every launch attempt today fails closed at `MISSING_CONFIG` before any request would be attempted — but even if credentials existed, this stage would not have exercised them against the real API. All verification of the launch/pause/resume/budget-update logic was done through the pure orchestration functions (`createCampaignStep`, `activateCampaignStep`, etc.) with injected mock `MetaAdsDeps` in `tests/ad-studio.test.ts`.
- **Per-variant Meta Ad object creation is deferred within `launch-ad-campaign`.** The function creates one Meta Campaign and one Ad Set, then activates the Campaign — it does not yet call `createAdStep` to create individual Meta Ad objects per creative variant, because that requires an intermediate ad-creative upload step (`POST /act_{id}/adcreatives`) this pass did not build. `createAdStep` and `CreateAdParams` exist and are exercised by unit tests, but are not wired into any live call site yet. This is flagged directly in the function's own source comment, not just here.
- **No live HTTP-invocation smoke test of any of the 8 new edge functions.** Every prior stage's status report has documented the same root constraint: no mintable operator JWT / no configured system-user token exists in this environment to call an Ideation-surface function end-to-end over HTTP as a real authenticated user. Verification instead relied on: the pure business-logic unit tests (42 new, covering every gate and validator each function calls), the live SQL-level schema/constraint verification above, and a byte-identical deploy diff for the highest-risk function.
- **No real Ad Opportunity has been promoted to a launched Campaign.** Same root cause every prior stage has carried forward: no real Content Opportunities/Items exist yet for the live client for `organic_winner` promotion to draw from, and — specific to this stage — no Meta ad account is configured to launch against even if a real Campaign were drafted.
- **Conversion tracking linkage beyond `attribution_requirements`/`attribution` jsonb fields.** The Ad Brief and Ad Campaign both carry structured attribution fields (`pixel_id`, `conversion_event`) that persist through creation, satisfying "Attribution identifiers persist," but no pixel-firing or server-side conversion-event integration was built — out of scope for a paid-distribution backbone with no live ad account to attribute against.
